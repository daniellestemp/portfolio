Simplifying My Research Workflow with get-bls-data

get-bls-data is a Python function that quickly pulls Bureau of Labor Statistics (BLS) data through its public API — built to smooth out a clunky part of my own research workflow.

01 · Challenge

Finding a single data point for a specific variable is surprisingly hard, even though it's a core part of data analysis and reporting. Even organized analysts can get lost navigating clunky government databases and juggling spreadsheets.

02 · Solution

get-bls-data references specific BLS data series IDs and returns the corresponding values in a clean table — the user enters a year, and the function displays the data for it.

03 · Process

Accessing APIs

BLS's sample developer code runs, but it's essentially uncommented. Working through the samples helped build general familiarity with the API, though much of it was either beyond my Python experience at the time or too narrow to reuse directly — so I went back to the sample code itself and iterated until it worked.

Identifying the right series

Unlike the Census Bureau, BLS doesn't provide a lookup key for its series IDs — just a format for each data category, leaving users to assemble the correct combination. After exploring BLS's data tools, I landed on the union-affiliation series from the Current Population Survey as my target data.

Understanding data structure

A lot of troubleshooting came down to understanding how BLS structures its series — including the difference between "annual" and "monthly" series — which BLS's Series Report tool helped clarify.

04 · Reflections

  • Limitations: the function currently only fetches the series hard-coded into it for a given year, though it's structured simply enough that swapping in new series IDs should be straightforward.
  • A starting point for analysis: it could support basic statistics, like tracking the average union membership rate from 2020–2024 or visualizing trends over time.
  • A reusable framework: not a one-size-fits-all solution, but a reasonable starting template for working with other public APIs.
  • Trouble-shooting pays off: nearly two and a half weeks were spent on the "extract and process results" section before realizing the issue was inconsistent date formats — a small fix that unlocked the rest of the build.
  • Coding in plain language first, then translating to code, opened up new problem-solving approaches.
